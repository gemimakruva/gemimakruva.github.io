Ch 12 Design for Reliability (Deep)

Bathtub Curve (Failure Rate vs Time)

  • Early life (infant mortality): λ tinggi, menurun. Penyebab: defect manufaktur, QC miss.
  • Useful life (constant failure rate): λ konstan. Random failures. Area di mana R(t) = e-λt berlaku.
  • Wear-out: λ meningkat. Penyebab: aging, korosi, fatigue.

Reliability Improvement Techniques

  • Parts selection: pilih komponen dengan proven reliability
  • Derating: operasikan di bawah rated capacity (misal 70%)
  • Redundancy: active (semua on) atau standby (switch on failure)
  • Screening/burn-in: eliminasi infant mortality sebelum delivery

FTA: Langkah Detail

  1. Definisikan Top Event (kegagalan sistem)
  2. Identifikasi penyebab langsung (intermediate events)
  3. Hubungkan dengan AND/OR gates
  4. Teruskan sampai basic events (komponen)
  5. Hitung probabilitas: AND = P(A) × P(B), OR = 1 - (1-P(A))(1-P(B))
  6. Identifikasi Minimal Cut Sets

FMEA/FMECA: Langkah Detail

  1. List semua komponen dan failure modes
  2. Tentukan efek (local, next level, system)
  3. Severity (1-10), Occurrence (1-10), Detection (1-10)
  4. RPN = S × O × D
  5. Prioritaskan RPN tertinggi untuk corrective action

Reliability vs Maintainability: Pendekatan Gabungan

Target: Ao = MTBM / (MTBM + MDT). Bisa dicapai dengan naikkan MTBM (reliability tinggi → jarang gagal) ATAU turunkan MDT (maintainability baik → cepat diperbaiki). Kombinasi keduanya paling cost-effective.

Ch 13 Design for Maintainability (Deep)

Maintainability vs Maintenance

  • Maintainability: design characteristic (inherent, di-design-kan masuk)
  • Maintenance: operational activity (dilakukan setelah beroperasi)

Design Principles

  • Accessibility: clearance, reach, visual access
  • Diagnostics: BIT (Built-In Test), external test points, fault indicators
  • Modular design: replaceable modules (LRU/Line Replaceable Unit, LRA/Line Replaceable Assembly), plug-and-play
  • Standardization: fasteners standar, common tools, interchangeable parts
  • Labeling & coding: identifikasi jelas pada setiap komponen

Maintenance Downtime Breakdown

Total Downtime MDT = Mct + Mpt + Logistic delay + Admin delay
Mct = Corrective maintenance time (perbaikan)
Mpt = Preventive maintenance time (pencegahan)
Logistic delay = tunggu spare parts, transportasi
Admin delay = tunggu keputusan, approval, paperwork

LCC: 12 Langkah Detail

  1. Define problem: scope, boundary, horizon waktu, assumptions
  2. Identify feasible alternatives: minimal 2 alternatif
  3. Select evaluation model: present value, annual cost, payback period
  4. Estimate cost factors: R&D, production, O&S, retirement per alternatif
  5. Apply discount rate: PV = Future / (1+i)n
  6. Establish evaluation criteria: minimize LCC, maximize ROI
  7. Perform sensitivity analysis: variasikan parameter kritis ±10-20%
  8. Rank alternatives: berdasarkan criteria
  9. Document assumptions & results
  10. Review by management/stakeholders
  11. Update cost estimates: as design matures (iteratif)
  12. Select preferred alternative

Break-even Analysis

Break-even Point BEP = Fixed Cost / (Revenue per unit - Variable Cost per unit)

HF, Reliability, Maintainability: Hubungan 3 Arah

SOAL WAJIB SETIAP TAHUN:
  • HF→Rel: HF buruk → human error naik → λ naik → R turun

Disposability:

Definisi: Kemampuan sistem untuk di-retire dan di-dispose secara aman, ekonomis, dan ramah lingkungan di akhir life cycle.

  • % material yang bisa di-recycle (target: >85%)

  • Waktu dekomisioning (minggu/bulan)

Definisi: Kemampuan sistem untuk beroperasi dengan dampak lingkungan minimal sepanjang seluruh life cycle (bukan hanya end-of-life).

Ukuran Kuantitatif:

  • Carbon footprint (kg CO2 equivalent per unit output)
  • Energy efficiency (output/input, atau kWh per unit)
  • % material ramah lingkungan / renewable material
  • Water consumption per unit output (m³/unit)
  • Waste reduction ratio (kg waste/kg product)
  • Life Cycle Assessment (LCA) score

Contoh: MRT Jakarta: emisi per penumpang-km jauh lebih rendah dari kendaraan pribadi, energi listrik (bisa dari renewable), mengurangi kemacetan (indirect sustainability benefit).

▶66%Life Cycle Costing (4 aspek & 12 langkah)

Pola: Baru muncul 2025 #8 (15 poin). Kemungkinan muncul lagi karena bobot besar.

Jawaban:

LCC (Life Cycle Cost) = total biaya sistem dari lahir sampai mati (cradle-to-grave). Tujuan: memilih alternatif desain yang paling cost-effective sepanjang seluruh life cycle.

4 Aspek (Kategori Biaya):

#KategoriContoh Komponen% Tipikal
1R&D CostDesain, prototyping, testing, engineering10-15%
2Production/Construction CostManufacturing, QC, delivery, facilities15-20%
3Operation & Support CostOperasional, maintenance, spare parts, training, logistik60-80%
4Retirement/Disposal CostDekomisioning, recycling, hazardous waste disposal5-10%
PENTING: O&S Cost adalah porsi terbesar (60-80% dari total LCC). Maka keputusan desain awal (Conceptual) yang mempengaruhi O&S sangat kritis. Ini alasan SE fokus di awal.

12 Langkah LCC:

  1. Define problem: scope, boundary, time horizon, assumptions
  2. Identify feasible alternatives: minimal 2 alternatif desain
  3. Select evaluation model: present value, annual cost, payback period
  4. Estimate cost factors: R&D, production, O&S, retirement per alternatif
  5. Apply discount rate: PV = Future Value / (1+i)n
  6. Establish evaluation criteria: minimize LCC, maximize ROI (Return on Investment), target BEP (Break-Even Point)
  7. Perform sensitivity analysis: variasikan parameter kritis ±10-20%
  8. Rank alternatives: berdasarkan criteria yang ditetapkan
  9. Document assumptions & results
  10. Review by management/stakeholders
  11. Update cost estimates: as design matures (iteratif setiap fase)
  12. Select preferred alternative

Break-even Point:

BEP = Fixed Cost / (Revenue per unit - Variable Cost per unit)
Kunci ujian: Hafal 4 aspek + urutan 12 langkah. Tekankan bahwa O&S cost dominan dan 50-75% LCC sudah committed di Conceptual Design meskipun biaya aktual (incurred) masih kecil.

Strategi Ujian

  • Prioritas 1: Hafal 5 soal wajib = 50 poin
  • Prioritas 2: Pahami framework studi kasus (FTA, FMEA, HF, maintainability)
  • Prioritas 3: LCC (4 aspek + 12 langkah)
  • Waktu: 100 menit / 8 soal = ~12 menit/soal
  • Format: Closed book, essay. Jawab dengan bahasa sendiri + contoh.

Aliran Pendingin

Teras reaktor → Pompa primer (dorong) → Heat exchanger (tukar panas) → Kembali ke teras. Loop tertutup, tekanan rendah.

Metode Pendekatan Analisis: PSA Level 1 + FTA

PSA (Probabilistic Safety Assessment) Level 1

  • Menghitung probabilitas core damage (kerusakan teras)
  • Mengidentifikasi initiating events dan failure sequences
  • Output: CDF (Core Damage Frequency)

FTA (Fault Tree Analysis): Langkah-langkah

  1. Definisikan Top Event: "Loss of Cooling Flow" (hilangnya aliran pendingin)
  2. Dekomposisi: Top event dipecah menjadi intermediate events (penyebab langsung)
  3. Hubungkan dengan logic gates: AND (semua harus gagal) dan OR (salah satu gagal)
  4. Terus ke bawah sampai basic events (kegagalan komponen individual)
  5. Masukkan failure rate data dari database atau data historis
  6. Hitung: Minimal Cut Sets, unavailability, importance measures

FMECA Analisis FMECA dan RCM

FMECA vs RCM

FMECA

Failure Modes, Effects, and Criticality Analysis

Mengidentifikasi fungsi, failure mode, dampak, dan tingkat kekritisan.

"Apa yang gagal, apa akibatnya, seberapa kritis?"

RCM

Reliability-Centered Maintenance

Menentukan tindakan pemeliharaan yang paling sesuai berdasarkan konsekuensi kegagalan.

"Apa yang harus dilakukan agar kegagalan dicegah atau cepat ditangani?"

Alur: Fakta kejadian (apa yang terjadi) → FMECA (failure mode, dampak, kekritisan) → Keputusan RCM (klasifikasi konsekuensi, jenis tugas) → Tindakan (pengujian, pemeliharaan, prosedur, redesign)

Catatan penting:

FMECA ini dilakukan after-the-fact (pasca-kejadian), bukan before-the-fact (saat desain). Idealnya, FMECA dilakukan sejak tahap desain untuk mencegah kelemahan lebih awal.

Hasil FMECA: Penyebab dan Deteksi Kegagalan

Temuan penting: ARD dan UPS sudah dirawat, tetapi kegagalannya tidak terdeteksi. Pemeliharaan perlu benar-benar menguji fungsi (failure-finding test), bukan hanya memeriksa keberadaan perangkat.

Dasar penilaian: severity (keparahan dampak) dengan kategori skala severity pada buku. Frequency dan detection belum dinilai karena data tidak cukup. Kekritisan ditentukan dari dampak terhadap keselamatan dan operasional, tanpa perhitungan numerik RPN.

RCM Klasifikasi Konsekuensi dan Tugas RCM

3 Klasifikasi Konsekuensi Kegagalan

Safety

Elevator, lampu emergency, PA, radio, prosedur evakuasi

Pendekatan: Prioritas tertinggi; redesign bila pemeliharaan tidak efektif

Operational

Suplai daya, CCTV, AC, pompa air, AFC/gate, respons teknisi

Pendekatan: On-condition, functional test, dukungan maintenance

Hidden Failure

Terjadi pada ARD, UPS, lampu darurat, komunikasi cadangan

Pendekatan: Failure-finding task: uji fungsi cadangan secara berkala

Hidden failure adalah temuan terpenting: ARD dan UPS sudah terpasang dan dirawat, tetapi tetap gagal saat dibutuhkan. Ini contoh nyata hidden failure yang hanya terdeteksi saat kejadian sesungguhnya. Solusi: failure-finding test (uji fungsi berkala dengan simulasi blackout).

Urutan Tindakan RCM (Prioritas)

  1. Verifikasi & failure-finding fungsi keselamatan: ARD, UPS, lampu emergency, PA darurat, komunikasi stasiun ke OCC (evaluasi cara pengujian yang ada)
  2. On-condition maintenance: CCTV, panel daya, kondisi baterai, pompa, AC, AFC/gate

  4. Mitigasi & redesign: bila pengujian tetap tidak cukup: tambah kapasitas atau redundansi daya cadangan, pisahkan sumber daya komunikasi, PA darurat

Perkiraan Pertanyaan UTS: Studi Kasus MRT Jakarta

▶TinggiIdentifikasi dan analisis 9 tugas manusia saat blackout. Evaluasi kekuatan dan kelemahan respons HF!

Jawaban:

9 tugas manusia: (1) Deteksi gangguan, (2) Komunikasi ke stasiun, (3) Evakuasi penumpang lift, (4) Pengarahan penumpang, (5) Aktivasi lampu darurat manual, (6) Koordinasi dengan PLN, (7) Monitoring pemulihan daya, (8) Reset sistem fasilitas, (9) Verifikasi kesiapan operasi.

Kekuatan: 0 korban jiwa, evakuasi lift berhasil, komunikasi OCC berjalan meski terganggu, koordinasi PLN cepat (4 menit), SOP dasar diikuti.

Kelemahan: Tim standby terbatas (tidak di setiap stasiun), komunikasi radio terganggu, simulasi belum menyeluruh, prosedur evakuasi lift belum terstandar, PA system gagal 2-3 jam, ketergantungan vendor.

Evaluasi: Respons HF secara keseluruhan memadai untuk keselamatan dasar (0 korban), tetapi belum memadai untuk pemulihan cepat. Gap terbesar: tidak ada komunikasi darurat redundan dan teknisi tidak tersedia di setiap stasiun.

▶TinggiJelaskan konsep hidden failure dalam kasus ini. Mengapa ARD dan UPS gagal meski sudah dirawat?

Jawaban:

Hidden failure: kegagalan yang tidak terdeteksi dalam kondisi operasi normal, dan baru terungkap saat kondisi darurat terjadi. Sistem cadangan (ARD, UPS, lampu emergency) adalah contoh tipikal hidden failure karena tidak digunakan sehari-hari.

Mengapa ARD dan UPS gagal meski sudah dirawat?

  • Pemeliharaan yang dilakukan kemungkinan hanya pemeriksaan visual atau administratif (cek ada/tidak, kondisi fisik), bukan pengujian fungsi
  • Baterai UPS bisa mengalami degradasi kapasitas tanpa terlihat dari luar
  • ARD elevator mungkin tidak pernah diuji dalam kondisi blackout sesungguhnya
  • Perpindahan otomatis (ATS/Automatic Transfer Switch) mungkin tidak aktif atau tidak terkonfigurasi benar

Solusi RCM: Failure-finding task, yaitu pengujian berkala yang benar-benar mensimulasikan kondisi kegagalan (simulasi blackout) untuk memverifikasi bahwa sistem cadangan berfungsi saat dibutuhkan.

▶TinggiLakukan analisis FMECA pada kasus blackout MRT. Identifikasi failure modes, severity, dan rekomendasi!

Jawaban:

4 Failure Modes utama:

  1. Lift berhenti, penumpang terjebak: Penyebab: hilangnya suplai listrik, ARD tidak berfungsi. Severity: Sangat Tinggi (keselamatan penumpang).
  2. Lampu emergency tidak menyala: Penyebab: baterai habis/degradasi, perpindahan otomatis gagal. Severity: Sangat Tinggi (area gelap, evakuasi terhambat).
  3. PA dan radio tidak berfungsi: Penyebab: UPS tidak aktif/tidak bertahan. Severity: Tinggi (informasi terhambat, koordinasi terganggu).
  4. Pemulihan lambat: Penyebab: teknisi terbatas, SOP tidak lengkap. Severity: Tinggi (downtime diperpanjang).

Catatan: Analisis ini bersifat kualitatif (berdasarkan severity saja) karena data frequency dan detection belum cukup untuk menghitung RPN = S x O x D.

Rekomendasi berdasarkan FMECA:

  • Failure-finding test berkala untuk semua sistem cadangan
  • Evaluasi kapasitas dan umur baterai UPS
  • Investigasi penyebab ARD gagal dan uji dengan simulasi blackout
  • Redundansi jalur komunikasi darurat
▶SedangAnalisis maintainability: mengapa listrik pulih 4 menit tetapi PA baru pulih 2-3 jam? Apa implikasinya?

Jawaban:

Perbedaan recovery time menunjukkan bahwa pemulihan daya tidak sama dengan pemulihan sistem:

  • Listrik PLN (4 menit): Sumber utama dipulihkan oleh PLN. Ini di luar kendali MRT, tetapi cepat.
  • PA system (2-3 jam): Memerlukan restart manual, konfigurasi ulang, dan kemungkinan keterlibatan vendor. Sistem PA kompleks: amplifier, speaker, controller, jaringan.

Implikasi maintainability:

  • MDT (Mean Down Time) bukan hanya Mct (corrective time). MDT = Mct + logistic delay + admin delay.
  • Logistic delay: menunggu teknisi/vendor datang ke stasiun
  • Admin delay: koordinasi, otorisasi, pencarian SOP
  • Untuk PA: MDT didominasi oleh logistic delay (vendor) dan technical complexity (restart)

Rekomendasi: Desain PA system agar bisa auto-restart pasca-pemulihan daya, atau sediakan PA darurat portabel yang tidak bergantung pada sistem utama.

Kehandalan dan Resiko (Topik 7)

  • Kehandalan (Reliability): probabilitas sistem beroperasi tanpa kegagalan selama periode tertentu dalam kondisi operasi tertentu

Return on Investment / ROI (Topik 8)

Optimasi (Topik 12)

  • Metode: trial & error, metode numerik, linear programming, heuristik

Pemodelan dan Simulasi (Topik 13)

  • Prinsip dasar: jangan pernah bereksperimen pada sistem nyata — uji dulu di model/simulasi
  • Physical modeling: model skala kecil di laboratorium
  • Digital modeling: simulasi komputer — ubah variabel, lihat hasil sebelum terapkan
Chernobyl 1986: ahli nuklir melakukan eksperimen langsung pada reaktor yang beroperasi, bukan pada simulasi. 6 lapis safety tidak dirancang untuk skenario eksperimen → cascading failure → bencana nuklir terburuk. Pelajaran: simulasi dulu, baru implementasi.

Analisis Multivariat (Topik 14)

  • Teknik analisis banyak variabel secara bersamaan — karena 4 aspek norma memiliki satuan berbeda

DMSS / Decision Making Support System (Topik 15)

  • Sistem yang mempercepat pengambilan keputusan: input masalah → proses → output rekomendasi

  • Contoh: dokter input gejala → sistem rekomendasikan diagnosis; tender → sistem bandingkan vendor

Big Data (Topik 16)

  • Kumpulan data dari banyak sumber; terpisah tidak berarti, digabung menjadi sangat berharga
  • AI (Artificial Intelligence) = penerapan teknik sistem pada big data, akurasi 90%+
  • Contoh: ChatGPT, pencarian nama seseorang di internet → data dari berbagai sumber disatukan

5 Indikator Aspek Teknik & Ekonomi

Aspek Teknik

  • Efisiensi Materi: seberapa efisien penggunaan bahan baku/material dalam sistem
  • Efisiensi Energi: rasio output energi terhadap input energi
  • Kapasitas Sistem: kemampuan maksimal sistem dalam menghasilkan output
  • Kualitas Hasil: mutu produk/output yang dihasilkan sistem
  • Kemudahan Operasional: tingkat kesulitan dalam mengoperasikan sistem
  • Compatibility: kemampuan sistem berinteraksi dengan sistem lain
  • Keandalan dan Resiko: probabilitas beroperasi tanpa kegagalan vs. kemungkinan gagal

Aspek Ekonomi

  • Payback Period: waktu pengembalian investasi
  • Break Even Point (BEP): titik impas di mana pendapatan = biaya total
  • Total Investasi: jumlah total modal yang dibutuhkan
  • Harga per Kapita: biaya per unit output atau per orang
  • ROI (Return on Investment): persentase pengembalian atas investasi
  • NPV (Net Present Value): nilai sekarang dari arus kas masa depan dikurangi investasi awal
6 Indikator Aspek Lingkungan FKBN & Sosial Budaya

Aspek Lingkungan FKBN

FKBN = Fisika, Kimia, Biologi, Nuklir

  • Dampak Fisika: kebisingan, getaran, radiasi elektromagnetik, perubahan suhu, tekanan
  • Dampak Kimia: emisi gas, limbah cair, kontaminasi tanah, polusi udara
  • Dampak Biologi: gangguan ekosistem, deforestasi, hilangnya biodiversitas
  • Dampak Nuklir/Radioaktivitas: kontaminasi radioaktif, paparan radiasi, limbah nuklir
  • Dampak Kesehatan Manusia: efek jangka pendek dan panjang terhadap kesehatan

Aspek Lingkungan Sosial Budaya

  • Safety (Keselamatan): tingkat keselamatan kerja dan pengguna sistem
  • Kenyamanan: tingkat kenyamanan dalam menggunakan/berada di sekitar sistem
  • Kreatifitas: apakah sistem mendorong atau menghambat kreativitas
  • Agresifitas: dampak terhadap perilaku agresif masyarakat
  • Agility (Kelincahan): kemampuan adaptasi sistem dan masyarakat terhadap perubahan
  • Productivity (Produktivitas): dampak terhadap produktivitas masyarakat/pekerja
7 Kehandalan dan Resiko

Kehandalan (Reliability)

  • Probabilitas sistem beroperasi tanpa kegagalan selama waktu tertentu, dalam kondisi operasi yang ditentukan
  • Diukur dengan: MTBF (Mean Time Between Failures), MTTF (Mean Time To Failure)
  • Faktor yang mempengaruhi: desain, material, lingkungan operasi, pemeliharaan

Resiko

  • Resiko = Probabilitas Kegagalan × Konsekuensi Kegagalan
  • Manajemen resiko: identifikasi → analisis → mitigasi → monitoring
  • Trade-off: biaya meningkatkan kehandalan vs. kerugian akibat kegagalan
8 ROI dan Payback Period

Return on Investment (ROI)

ROI = (Keuntungan Bersih / Total Investasi) × 100%
  • Mengukur efisiensi investasi dalam bentuk persentase
  • ROI > 0% berarti investasi menguntungkan
  • Digunakan untuk membandingkan kelayakan ekonomi beberapa alternatif sistem

Payback Period

Payback Period = Total Investasi / Keuntungan Bersih per Periode
  • Waktu yang dibutuhkan agar kumulatif keuntungan = total investasi
  • Semakin pendek → semakin baik (modal lebih cepat kembali)
  • Kelemahan: tidak memperhitungkan time value of money (berbeda dengan NPV)

Contoh: tubuh manusia (semua subsistem teridentifikasi), Indonesia (34 provinsi), MeTSi (mahasiswa, dosen, pamong, kurikulum, fasilitas).

#3 5 poin Jelaskan apa yang dimaksud dengan Organismik dalam wawasan sistemik.

Organismik = koordinasi program, sumber daya dan komponen sistem.

Pilar kedua wawasan sistemik. Fokus pada interkoneksi dan koordinasi antar komponen sistem. Prinsip kunci: satu kata, satu makna — semua anggota sistem harus memiliki pemahaman yang sama terhadap terminologi. Komunikasi yang gagal = sistem yang gagal. Setiap elemen memiliki job description spesifik; kesalahan pada satu elemen berdampak pada seluruh sistem (cascading effect).

Contoh: tubuh manusia (saraf-otot-rangka terkoordinasi), MeTSi (dosen-kurikulum-mahasiswa-fasilitas saling terhubung). Analogi tim sepak bola: 9 pemain yang terkoordinasi baik memiliki kapasitas setara 625+ orang — sinergi eksponensial melalui koordinasi.

#4 5 poin Jelaskan apa yang dimaksud dengan Continuous Improvement.

Continuous Improvement = proses peningkatan berkelanjutan — mengenal kondisi sekarang, menentukan target yang lebih baik, lalu bergerak menuju target tersebut secara terus-menerus. Siklus: Evaluasi → Identifikasi kelemahan → Optimasi → Rancang perbaikan → Implementasi → Evaluasi lagi. Prinsip: “Besok harus lebih baik dari hari ini” (Ir. Supranto). Berkaitan erat dengan wawasan sintetik dan siklus PSOME yang berjalan tanpa henti. Setiap siklus menghasilkan evaluasi yang menjadi input planning berikutnya, sehingga sistem berkembang dari “berfungsi baik” menjadi “berfungsi lebih baik”.

#5 5 poin Jelaskan indikator unjuk kerja sistem: aspek teknik dan aspek ekonomi.

Aspek Teknik: efisiensi materi, efisiensi energi, kapasitas sistem, kualitas hasil, kemudahan operasional, compatibility, keandalan dan resiko.

Aspek Ekonomi: payback period, BEP, total investasi, harga per kapita, ROI, NPV.

Keduanya merupakan 2 dari 4 aspek indikator yang digunakan untuk menilai unjuk kerja (performance) suatu sistem.

#6 5 poin Jelaskan indikator unjuk kerja sistem: aspek lingkungan fisik dan aspek lingkungan budaya.

Aspek Lingkungan FKBN: dampak fisika (kebisingan, getaran), dampak kimia (emisi, limbah), dampak biologi (ekosistem), dampak nuklir/radioaktivitas, dampak kesehatan manusia.

Aspek Lingkungan Sosial Budaya: safety, kenyamanan, kreatifitas, agresifitas, agility, productivity.

Gabungan 4 aspek (teknik, ekonomi, FKBN, sosial budaya) menghasilkan Performance Index yang menentukan kualitas sistem secara keseluruhan.

#7 5 poin Jelaskan tentang Kehandalan dan Resiko.

Kehandalan (Reliability) = probabilitas sistem beroperasi tanpa kegagalan selama periode tertentu pada kondisi operasi tertentu. Risiko = potensi kejadian merugikan; setiap sistem memiliki risiko, bahkan probabilitas 1% tetap bisa terjadi.

Mitigasi risiko: (1) preventive — mencegah terjadinya kegagalan, (2) contingency — menyiapkan rencana darurat jika terjadi. Contoh desain pabrik: jalur evakuasi terpisah, titik kumpul (assembly point), larangan benda logam & HP di area bahaya, SOP (Standard Operating Procedure) darurat. Semua skenario kegagalan harus memiliki perlindungan. Safety adalah prioritas #1.

#8 5 poin Jelaskan tentang ROI dan Payback Period.
ROI = (Keuntungan Bersih / Total Investasi) × 100%
Payback Period = Total Investasi / Keuntungan Bersih per Periode

ROI mengukur efisiensi investasi (ROI > 0% = untung). Payback period mengukur waktu pengembalian modal (semakin pendek semakin baik). Keduanya termasuk indikator aspek ekonomi. Kelemahan payback period: tidak memperhitungkan time value of money.

#9 5 poin Jelaskan tentang Planning and Staffing.

Planning: tahap pertama PSOME. Menetapkan tujuan, identifikasi komponen dan interkoneksi, menyusun program kerja, menentukan performance indicators, dan standar 4 aspek norma. Menggunakan 12 pertanyaan kunci pembentukan sistem.

Staffing: tahap kedua PSOME. Menempatkan SDM yang tepat pada posisi yang tepat, memastikan kompetensi sesuai kebutuhan, dan pengembangan kapasitas melalui pelatihan.

#10 5 poin Jelaskan tentang Operating and Organizing.

Operating: menjalankan sistem sesuai perencanaan dan prosedur. Implementasi program kerja, memastikan setiap komponen berfungsi.

Organizing: mengatur koordinasi antar komponen, alokasi sumber daya, menetapkan alur kerja dan hierarki. Penerapan praktis dari wawasan organismik.

#11 5 poin Jelaskan tentang Monitoring and Evaluation.

Monitoring: pengawasan kinerja real-time/berkala menggunakan performance indicators, deteksi dini penyimpangan, pengumpulan data.

Evaluation: penilaian menyeluruh berdasarkan 4 aspek norma, analisis gap (aktual vs. target), rekomendasi perbaikan. Hasil evaluasi menjadi input planning berikutnya (continuous improvement).

#12 5 poin Jelaskan tentang Optimasi.

Optimasi = mencari yang terbaik dari beberapa pilihan/alternatif (minimal 3 alternatif). Hadir di setiap tahap rekayasa sistem: rancang optimasi → bangun → operasi → evaluasi → optimasi lagi. Proses: bandingkan alternatif → ukur berdasarkan 4 aspek norma → urutkan dari terbaik → pilih optimal. Berjenjang: sistem → subsistem → sub-subsistem (holistik). Inti dari wawasan sintetik. Contoh: memilih laptop dari 5 pilihan berdasarkan spesifikasi (aspek teknik) dan harga (aspek ekonomi) — itu teknik sistem.

#13 5 poin Jelaskan tentang Pemodelan dan Simulasi.

Prinsip dasar: jangan pernah bereksperimen langsung pada sistem yang sedang beroperasi — uji dulu pada model/simulasi. Pemodelan: membuat representasi sistem (fisik skala kecil di lab, atau digital/komputer). Simulasi: menjalankan model, mengubah variabel, melihat dampak sebelum diterapkan di dunia nyata. Pelajaran: simulasi & modeling adalah WAJIB sebelum mengubah sistem nyata.

#14 5 poin Jelaskan tentang Analisis Multivariat.

Analisis Multivariat = teknik analisis yang mempertimbangkan banyak variabel/aspek secara bersamaan. Relevan karena setiap sistem memiliki 4 aspek norma dengan satuan berbeda (kualitatif & kuantitatif). Masalah utama: bagaimana mendapatkan nilai total baik/buruk sebuah sistem sehingga beberapa sistem dapat diperbandingkan? Metode: pembobotan aspek, normalisasi nilai, scoring, ranking, regresi multivariat, PCA. Analisis multivariat adalah alat untuk optimasi — membantu mengurutkan pilihan secara objektif ketika alternatif unggul di aspek yang berbeda-beda.

#15 5 poin Jelaskan tentang Decision Making Support System (DMSS).

DMSS = sistem/program yang mempercepat dan meningkatkan kualitas pengambilan keputusan. Input masalah/data → proses (sorting, perbandingan, analisis berdasarkan 4 aspek) → output rekomendasi. Mengurangi waktu keputusan dari berjam-jam menjadi sekali klik. Bagian dari optimasi. Contoh: (1) Medis — dokter input gejala, sistem rekomendasikan diagnosis & obat, (2) Pendaftaran sekolah — input data siswa, sistem sortir prioritas, (3) Tender — input proposal vendor, sistem bandingkan & urutkan. Big Data = kumpulan dari berbagai macam data dari banyak sumber yang jika terpisah tidak berarti, tetapi ketika digabung dan diproses menjadi informasi sangat berharga. Data tersebar di berbagai format dan lokasi; teknik sistem menyatukannya menjadi program yang bisa menjawab masalah. 1. Persamaan Non-Linear

Metode Bisection

4. Pengaruh ΔT

  • ΔT besar → error besar, grafik kasar
  • ΔT kecil → akurat, grafik smooth

6. Euler Mundur (Backward/Implicit)

Implisit Euler Mundur
Euler Munduryj = yj-1 + f(tj, yj) · ΔT
  • f dievaluasi di titik j (belum diketahui), bukan j-1 → metode implisit
  • Derivasi: deret Taylor mundur, Y(T-ΔT) = Y(T) - Y'·ΔT + ...
  • Truncation error: O1b = -½Y''·ΔT² (negatif, vs positif pada Euler Maju)
  • Lebih stabil untuk ODE stiff (perubahan sangat cepat)

7. Modified Euler (Prediktor-Korektor)

O(ΔT²) Metode Dua Langkah

Langkah 1: Prediktor (Euler Maju biasa)

Prediktoryj,p = yj-1 + f(tj-1, yj-1) · ΔT

Langkah 2: Korektor (rata-rata slope awal dan akhir, iteratif)

Korektoryj,k,r = yj-1 + ½[f(tj-1, yj-1) + f(tj, yj,k,r-1)] · ΔT

Konvergensi

Kriteriaεj,r = |yj,k,r - yj,k,r-1| ≤ Δε

Inisialisasi: r=1 memakai yj,k,0 = yj,p (hasil prediktor).

Inti: Euler Standar pakai slope di titik awal saja. Modified Euler rata-ratakan slope awal + akhir, sehingga error turun dari O(ΔT) ke O(ΔT²).

Topik 1 Teknologi Informasi & Komputer

Definisi Teknologi Informasi

  • Teknologi: artefak (buatan manusia) yang membantu atau mengatasi kekurangan manusia
  • Teknologi Informasi: teknologi yang digunakan untuk mengolah informasi — mencakup perangkat keras, perangkat lunak, jaringan, dan proses yang terlibat dalam pengumpulan, penyimpanan, pengolahan, dan distribusi data

Data vs Informasi

Data = fakta mentah, belum diolah. Contoh: beras, sabun, shampoo di rak supermarket.
Informasi = data yang sudah diolah sehingga bermakna dan berguna. Contoh: tagihan total yang harus dibayar di kasir.
Proses: Data → Pengolahan (sorting, kalkulasi, filtering) → Informasi

Topik 2 Internet of Things & Cyber Physical System

Internet of Things (IoT)

  • IoT: jaringan perangkat fisik (things) yang saling terhubung melalui internet, mampu mengumpulkan dan bertukar data
  • Things bukan hanya laptop/smartphone — termasuk sensor, microprocessor kecil, embedded computer, actuator, bahkan peralatan rumah tangga (smart home)
  • Setiap thing memiliki identitas unik (IP address) dan dapat berkomunikasi tanpa intervensi manusia (M2M: Machine-to-Machine)

Arsitektur Cyber Physical System (CPS)

Alur CPS:
Sensor (mengumpulkan data dari dunia fisik) → Komputer/Edge Device (pra-pemrosesan) → Router/Gateway (mengirim data) → Cloud (penyimpanan & komputasi besar) → Analysis (AI/ML memproses data) → Decision (keputusan otomatis/rekomendasi) → Actuator (aksi di dunia fisik)

CPS = integrasi dunia siber (software, data, AI) dengan dunia fisik (sensor, actuator, mesin)

Manfaat IoT

  • Automasi: proses otomatis tanpa intervensi manual (smart factory, smart farming)
  • Efisiensi: optimasi penggunaan energi, waktu, dan sumber daya
  • Alert & Safety: deteksi dini bahaya (sensor kebakaran, gempa, kebocoran gas)
  • Monitoring Real-time: pantau kondisi mesin, kesehatan, lingkungan secara langsung
  • Data-Driven Decision: keputusan berdasarkan data aktual, bukan intuisi

Risiko IoT

  • Security: perangkat IoT rentan terhadap hacking — lebih banyak titik masuk (attack surface)
  • Data Leakage: data pribadi bisa bocor jika enkripsi lemah
  • Ketergantungan Sistem: jika jaringan/server down, seluruh sistem terdampak
  • Privasi: sensor terus mengumpulkan data — potensi surveillance tanpa consent
  • Interoperability: standar berbeda antar vendor menyulitkan integrasi

Topik 1 Teknologi Informasi & Komputer — Detail

Apa Itu Teknologi?

  • Teknologi = artefak buatan manusia untuk membantu atau mengatasi kekurangan manusia
  • Bukan hanya gadget — palu, roda, tulisan, kacamata semua termasuk teknologi
  • Teknologi berkembang dari kebutuhan: manusia tidak bisa terbang → pesawat; tidak bisa hitung cepat → komputer

Informasi: Dari Data ke Knowledge

  • Data: fakta mentah tanpa konteks (angka, teks, gambar yang belum diolah)
  • Informasi: data yang sudah diolah, memiliki makna dan relevansi
  • Knowledge: informasi yang dipahami dan dapat diterapkan untuk pengambilan keputusan
  • Wisdom: kemampuan menerapkan knowledge dengan judgment yang tepat

Hierarki: Data → Informasi → Knowledge → Wisdom (DIKW Pyramid)

Komputer: Lebih dari Sekadar PC

  • Komputer = perangkat elektronik yang menerima input, memproses sesuai instruksi, dan menghasilkan output
  • Definisi luas: setiap perangkat dengan 5 komponen dasar adalah komputer (smartphone, smartwatch, ATM, smart TV, ECU mobil)
  • Embedded computer: komputer yang tertanam di perangkat lain (kulkas pintar, mesin cuci, sensor industri)

Detail 5 Komponen

1. Input Device — konversi data dari dunia luar ke sinyal digital:

  • Manual: keyboard, mouse, touchscreen, stylus
  • Otomatis: sensor (suhu, tekanan, cahaya, gerak), kamera, barcode scanner, GPS receiver
  • Biometrik: fingerprint reader, face recognition, iris scanner

2. Processing Unit — otak komputer:

  • CPU: ALU (Arithmetic Logic Unit) + Control Unit + Register + Cache
  • GPU: awalnya untuk grafis, kini digunakan juga untuk AI/ML training (parallel processing)
  • SoC: System on Chip — CPU, GPU, modem, ISP terintegrasi dalam satu chip (contoh: Apple A-series, Qualcomm Snapdragon)
  • Kecepatan diukur dalam GHz (miliaran operasi per detik)

3. Output Device — menyampaikan hasil ke pengguna atau lingkungan:

  • Visual: monitor, layar (LCD, OLED, E-ink)
  • Audio: speaker, headphone
  • Fisik: printer (2D/3D), actuator (motor, valve, relay)
  • Haptic: vibration motor (notifikasi getar di smartphone)

4. Storage — menyimpan data:

  • Volatile (hilang saat mati): RAM (DDR4/DDR5) — cepat tapi sementara
  • Non-volatile (permanen): HDD (magnetic), SSD (flash/NAND), eMMC, cloud storage
  • Hierarki: Register > Cache > RAM > SSD > HDD > Cloud (kecepatan ↓, kapasitas ↑, harga/GB ↓)

5. Communication — konektivitas:

  • Wired: Ethernet (LAN), USB, HDMI, Thunderbolt
  • Wireless: Wi-Fi, Bluetooth, NFC, Zigbee, LoRa, 4G/5G, satelit
  • Internet = jaringan global yang menghubungkan miliaran perangkat

Konsep Dasar IoT

  • IoT pertama kali dikonsepkan oleh Kevin Ashton (1999) — awalnya untuk RFID dan supply chain

  • Contoh CPS: self-driving car (sensor lidar/kamera → algoritma navigasi → steering/braking), smart grid (sensor beban → optimasi distribusi energi → kontrol transformator)

Topik 3 Machine Learning & Deep Learning — Detail

Dari AI ke Machine Learning

  • AI (Artificial Intelligence): bidang ilmu komputer yang membuat mesin mampu meniru kecerdasan manusia (reasoning, learning, problem solving)
  • Machine Learning: cabang AI di mana komputer belajar dari data tanpa diprogram secara eksplisit untuk setiap skenario
  • Paradigma tradisional: programmer menulis aturan (if-then). ML: komputer menemukan aturan sendiri dari data.

Supervised Learning — Detail

  • Data training memiliki label (jawaban yang benar sudah diketahui)
  • Model belajar memetakan input (fitur) → output (label)
  • Regresi: output berupa nilai kontinu
    • Contoh: prediksi harga rumah berdasarkan luas, lokasi, jumlah kamar
    • Algoritma: Linear Regression, Polynomial Regression, Decision Tree Regression
    • Grafik: x = fitur, y = nilai target → garis/kurva best fit
  • Klasifikasi: output berupa kategori/kelas
    • Contoh: email spam vs. tidak spam, diagnosis penyakit, deteksi objek
    • Algoritma: Logistic Regression, SVM, Random Forest, Neural Network

Unsupervised Learning — Detail

  • Data training tidak memiliki label — model menemukan pola sendiri
  • Clustering: mengelompokkan data berdasarkan kemiripan (K-Means, DBSCAN, Hierarchical)
  • Dimensionality Reduction: menyederhanakan data berdimensi tinggi (PCA, t-SNE)
  • Association: menemukan hubungan antar item (market basket analysis — “pembeli yang beli roti juga beli mentega”)

Reinforcement Learning — Detail

  • Agent berinteraksi dengan environment, mengambil action, menerima reward atau punishment
  • Tujuan: memaksimalkan cumulative reward jangka panjang
  • Tidak ada dataset — agent belajar melalui trial-and-error
  • Contoh: AlphaGo (game Go), robot belajar berjalan, self-driving car, optimasi routing jaringan

Deep Learning — Detail

  • Neural Network: terinspirasi dari neuron otak manusia
  • Perceptron: unit dasar — menerima input, kalikan weight, tambah bias, lewatkan fungsi aktivasi
  • Rumus neuron: y = f(w1x1 + w2x2 + ... + b) di mana f = fungsi aktivasi non-linear
  • Arsitektur: Input Layer → Hidden Layer(s) → Output Layer
  • “Deep” = banyak hidden layer (puluhan hingga ratusan)
  • Training: Forward propagation → Loss calculation → Backpropagation → Weight update (Gradient Descent)

Generative AI — Cara Kerja ChatGPT

  1. Pre-training (Supervised): model dilatih pada miliaran teks internet — belajar memprediksi kata berikutnya (next-token prediction)
  2. SFT (Supervised Fine-Tuning): dilatih ulang pada contoh percakapan berkualitas tinggi
  3. RLHF: manusia memberi ranking pada respons model → reward model dilatih → model di-optimize dengan PPO (Proximal Policy Optimization)

Hasilnya: model yang tidak hanya pintar menulis teks, tapi juga mengikuti instruksi dan menghindari output berbahaya.

▶PastiSoal #2: Jenis pembelajaran ML & ChatGPT

Soal: Sebut dan jelaskan jenis pembelajaran (learning types) pada Machine Learning. ChatGPT digolongkan ke kategori apa?

Jawaban Model:

Terdapat 3 jenis pembelajaran utama pada Machine Learning:

1. Supervised Learning — model belajar dari data yang memiliki label (pasangan input-output yang benar).

  • Regresi: memprediksi nilai kontinu (berapa?). Contoh: prediksi harga rumah, suhu besok.

Terdapat 3 jenis pembelajaran utama pada Machine Learning:

1. Supervised Learning (Pembelajaran Terawasi)

Model belajar dari data yang memiliki label — setiap input memiliki output yang benar (jawaban sudah diketahui).

  • Regresi: memprediksi nilai kontinu. Contoh: prediksi harga rumah berdasarkan luas dan lokasi, prediksi suhu besok berdasarkan data historis.
  • Klasifikasi: memprediksi kategori/kelas. Contoh: email spam vs. bukan spam, diagnosis penyakit (positif/negatif), deteksi wajah.

2. Unsupervised Learning (Pembelajaran Tidak Terawasi)

Model belajar dari data tanpa label — menemukan pola, struktur, atau kelompok tersembunyi secara mandiri.

  • Clustering: mengelompokkan data berdasarkan kemiripan. Contoh: segmentasi pelanggan berdasarkan perilaku belanja.
  • Dimensionality Reduction: menyederhanakan data berdimensi tinggi. Contoh: PCA untuk visualisasi data.
  • Pattern Discovery: menemukan asosiasi. Contoh: market basket analysis (“pembeli roti juga beli mentega”).

3. Reinforcement Learning (Pembelajaran Penguatan)

Agent belajar melalui interaksi dengan lingkungan. Tidak ada dataset — belajar dari trial-and-error dengan sistem reward (imbalan jika benar) dan punishment (hukuman jika salah). Tujuan: memaksimalkan cumulative reward jangka panjang.

Mengapa Supervised Learning?

Karena data sudah berlabel — kita memiliki pasangan input-output yang diketahui:

  • Input (x): waktu dalam jam (fitur/variabel independen)
  • Output (y): jumlah kendaraan per bulan (label/variabel dependen)

Mengapa Regresi (bukan Klasifikasi)?

Karena output yang diprediksi berupa nilai kontinu (jumlah kendaraan = angka numerik), bukan kategori/kelas diskrit.

  • Regresi: “Berapa jumlah kendaraan pada jam 14:00?” → jawaban angka (misal: 342 kendaraan)

Implementasi

  1. Linear Regression (y = ax + b): jika hubungan x-y cenderung linear (naik/turun konstan). Sederhana dan mudah diinterpretasi.

Proses:

  1. Kumpulkan data historis (x1,y1), (x2,y2), ..., (xn,yn)
  2. Latih model regresi — temukan fungsi y = f(x) yang paling mendekati semua titik data (minimasi error/loss)
  3. Gunakan model untuk memprediksi y pada nilai x baru (waktu tertentu)
Ringkasan:
• Data berlabel (ada x dan y) → Supervised (bukan Unsupervised)
• Output kontinu (angka) → Regresi (bukan Klasifikasi)
• Bukan Reinforcement karena bukan interaksi agent-environment
• Algoritma: Linear Regression atau Polynomial Regression

Topik 1 Statistik Deskriptif

Ukuran Pemusatan (Central Tendency)

  • Mean (rata-rata): x̄ = Σxi / n — jumlah seluruh data dibagi banyaknya data
  • Median: nilai tengah data yang sudah diurutkan. Jika n genap: rata-rata dua nilai tengah
  • Modus: nilai yang paling sering muncul (frekuensi tertinggi)

Ukuran Penyebaran (Dispersion)

  • Range: max − min
  • Variance (ragam): s² = Σ(xi − x̄)² / (n−1) — menggunakan n−1 untuk sampel (Bessel’s correction)
  • Standard Deviation: s = √s² — satuan sama dengan data asli

Penyajian Data

  • Tabel frekuensi: mengelompokkan data ke dalam kelas interval, mencatat frekuensi tiap kelas
  • Histogram: grafik batang dari tabel frekuensi, sumbu-x = kelas interval, sumbu-y = frekuensi
  • Box plot: menampilkan Q1, median, Q3, min, max, dan outlier
Konteks Ujian: Digunakan untuk soal PT Sunrise (bola voli) — hitung mean, std dev, buat histogram, lalu interpretasi apakah produk memenuhi standar.
Topik 2 Distribusi Probabilitas Empiris

Konsep Utama

  • Distribusi berdasarkan data observasi langsung (bukan asumsi distribusi teoritis)
  • Probabilitas dihitung dari frekuensi relatif data aktual

Langkah Penyusunan

  1. Tentukan sample space: daftar semua nilai unik yang muncul dalam data
  2. Buat tabel frekuensi: hitung berapa kali setiap nilai muncul (fi)
  3. Hitung probabilitas: P(X=x) = f(x) / n — frekuensi dibagi total observasi

Perhitungan Kunci

  • Rata-rata distribusi: μ = Σ[xi × P(xi)] — expected value
  • Peluang range: P(a ≤ X ≤ b) = Σ P(X=xi) untuk semua a ≤ xi ≤ b
  • Variance: σ² = Σ[(xi − μ)² × P(xi)]
  • Std Dev: σ = √σ²
Keyakinan 90% (one-sided upper): xmax = μ + z0.90 × σ = μ + 1.282σ
Artinya: 90% data diperkirakan ≤ xmax

Contoh khas: data perjalanan rumah-sekolah 15 atau 20 hari — hitung distribusi, rata-rata, peluang range, keyakinan 90%.

Topik 3 Distribusi Normal

Karakteristik

  • Bell curve, simetris terhadap mean (μ)
  • Ditentukan oleh dua parameter: μ (mean) dan σ (std dev)
  • Total area di bawah kurva = 1
  • Empirical rule: 68% dalam ±1σ, 95% dalam ±2σ, 99.7% dalam ±3σ

Standardisasi (Z-Score)

Z = (X − μ) / σ
Mengubah distribusi normal N(μ, σ²) menjadi N(0, 1)

Penggunaan Tabel Z

  • Φ(z) = P(Z ≤ z): luasan di sebelah kiri nilai z pada kurva normal standar
  • P(a ≤ X ≤ b) = Φ((b−μ)/σ) − Φ((a−μ)/σ)
  • P(X ≥ a) = 1 − Φ((a−μ)/σ)

Confidence Interval

  • CI 90% two-sided: x̄ ± 1.645σ — rentang yang memuat 90% data
  • CI 90% one-sided upper: xmax = μ + 1.282σ
  • CI 95% two-sided: x̄ ± 1.960σ
Perbedaan Empiris vs Normal:
• Empiris: dari data langsung, tanpa asumsi bentuk distribusi, cocok untuk sampel kecil
• Normal: asumsi distribusi teoritis bell-curve, cocok untuk populasi besar atau data yang diketahui mendekati normal
Topik 4 Uji Hipotesis

Langkah Uji Hipotesis

  1. Rumuskan hipotesis: H₀ (null) dan H₁ (alternatif)
  2. Pilih tingkat signifikansi: α (biasanya 0.05)
  3. Hitung statistik uji (t-hitung)
  4. Tentukan ttabel berdasarkan α dan df
  5. Keputusan: bandingkan |thitung| dengan ttabel

Uji-t Dua Sampel Independen

  • H₀: μ₁ = μ₂ (tidak ada perbedaan rata-rata)
  • H₁: μ₁ ≠ μ₂ (ada perbedaan rata-rata)
t = (x̄₁ − x̄₂) / √(s₁²/n₁ + s₂²/n₂)

Derajat Kebebasan (Welch’s Approximation)

df = (s₁²/n₁ + s₂²/n₂)² / [(s₁²/n₁)²/(n₁−1) + (s₂²/n₂)²/(n₂−1)]

Keputusan

  • |thitung| > ttabel → tolak H₀ → ada perbedaan signifikan
  • |thitung| ≤ ttabel → gagal tolak H₀ → tidak cukup bukti ada perbedaan
Contoh ujian: pakan impor (kelompok A) vs lokal (kelompok B) pada berat ayam — apakah ada perbedaan signifikan berat rata-rata?
Topik 5 Regresi & Korelasi

Regresi Linear Sederhana

y = a + bx

b = [nΣxy − ΣxΣy] / [nΣx² − (Σx)²]
a = ȳ − bx̄
  • b (slope): perubahan y untuk setiap kenaikan satu unit x
  • a (intercept): nilai y ketika x = 0

Koefisien Korelasi (r)

  • r = 1: korelasi positif sempurna
  • r = −1: korelasi negatif sempurna
  • r = 0: tidak ada korelasi linear
  • |r| > 0.8: korelasi kuat, 0.5–0.8: sedang, <0.5: lemah

Koefisien Determinasi (r²)

  • r² = persentase variasi y yang dapat dijelaskan oleh x
  • Contoh: r² = 0.85 berarti 85% variasi y dijelaskan model regresi

Regresi Polynomial

y = a₀ + a₁x + a₂x² + a₃x³ + …
Digunakan ketika hubungan x dan y tidak linear
Topik 6 Interpolasi

Konsep

Estimasi nilai di antara titik-titik data yang sudah diketahui. Berbeda dengan ekstrapolasi yang memperkirakan di luar rentang data.

Interpolasi Linear (2 titik)

y = y₁ + [(x − x₁) / (x₂ − x₁)] × (y₂ − y₁)

Menghubungkan dua titik (x₁, y₁) dan (x₂, y₂) dengan garis lurus, lalu estimasi y untuk x di antara keduanya.

Interpolasi Lagrange (n titik)

L(x) = Σ yi × ∏j≠i (x − xj) / (xi − xj)

Menggunakan semua n titik data untuk membuat polinomial berderajat (n−1). Akurasi lebih tinggi daripada linear.

Inverse Interpolation

  • Jika diketahui nilai y dan ingin mencari x → tukar peran x dan y dalam formula
  • Atau: gunakan interpolasi biasa dengan x sebagai fungsi dari y
Contoh ujian (Pirolisis): Data suhu vs komposisi produk (arang%, bio-oil%, gas%). Gas% = 100 − arang% − bio_oil%. Cari suhu untuk gas = 60% menggunakan interpolasi linear antara dua titik yang mengapit.

Topik 1 Statistik Deskriptif — Detail

Mean: Langkah Perhitungan

  1. Jumlahkan semua data: Σxi
  2. Bagi dengan jumlah data: x̄ = Σxi / n

Contoh Worked Example

Data berat bola voli (gram): 260, 262, 265, 268, 270, 271, 273, 275, 278, 280

  • Σxi = 2702
  • n = 10
  • x̄ = 2702/10 = 270.2 gram

Variance & Std Dev: Langkah

  1. Hitung mean (x̄)
  2. Untuk setiap data, hitung deviasi: di = xi − x̄
  3. Kuadratkan setiap deviasi: di²
  4. Jumlahkan: Σdi²
  5. Bagi dengan (n−1): s² = Σdi² / (n−1)
  6. Akar kuadrat: s = √s²

Membuat Histogram

  1. Tentukan jumlah kelas (Sturges: k = 1 + 3.322 log n)
  2. Hitung lebar kelas: h = range / k
  3. Tentukan batas kelas
  4. Hitung frekuensi tiap kelas
  5. Gambar batang dengan tinggi = frekuensi

Interpretasi

  • Jika histogram simetris → data mendekati normal
  • Skewness positif: ekor ke kanan (mean > median)
  • Skewness negatif: ekor ke kiri (mean < median)
  • Bandingkan mean ± std dev dengan spesifikasi produk untuk kesimpulan QC

Topik 4 Uji Hipotesis — Detail

Worked Example: Pakan Ayam Impor vs Lokal

Kelompok A (impor): n₁ = 10 ekor, x̄₁ = 2.5 kg, s₁ = 0.3 kg
Kelompok B (lokal): n₂ = 10 ekor, x̄₂ = 2.2 kg, s₂ = 0.4 kg
α = 0.05 (two-tailed)

Langkah 1: Rumuskan Hipotesis

  • H₀: μ₁ = μ₂ (tidak ada perbedaan berat rata-rata)
  • H₁: μ₁ ≠ μ₂ (ada perbedaan berat rata-rata)

Langkah 2: Hitung t-hitung

t = (x̄₁ − x̄₂) / √(s₁²/n₁ + s₂²/n₂)
= (2.5 − 2.2) / √(0.09/10 + 0.16/10)
= 0.3 / √(0.009 + 0.016)
= 0.3 / √0.025
= 0.3 / 0.1581
= 1.897

Langkah 3: Derajat Kebebasan (Welch)

df = (s₁²/n₁ + s₂²/n₂)² / [(s₁²/n₁)²/(n₁−1) + (s₂²/n₂)²/(n₂−1)]
= (0.025)² / [(0.009)²/9 + (0.016)²/9]
= 0.000625 / [0.000009 + 0.0000284]
= 0.000625 / 0.0000374
≈ 16.7 → df = 16

Langkah 4: Bandingkan dengan t-tabel

  • ttabel (α=0.05, two-tailed, df=16) = 2.120
  • |thitung| = 1.897 < 2.120 = ttabel

Langkah 5: Keputusan

Gagal tolak H₀. Pada α = 0.05, tidak cukup bukti untuk menyatakan ada perbedaan signifikan antara berat rata-rata ayam yang diberi pakan impor dan lokal.

Step Panduan Langkah per Tipe Soal

Soal Distribusi Empiris

  1. Urutkan data, buat tabel frekuensi
  2. Hitung P(X=x) = f/n untuk setiap nilai
  3. Hitung μ = Σ[x × P(x)]
  4. Hitung σ² = Σ[(x−μ)² × P(x)], lalu σ = √σ²
  5. P(range) = jumlahkan P(x) dalam range
  6. Keyakinan 90%: xmax = μ + 1.282σ

Soal Distribusi Normal

  1. Identifikasi μ dan σ (dari data atau soal)
  2. Hitung Z = (X−μ)/σ untuk setiap batas
  3. Cari Φ(z) di tabel Z
  4. P(a≤X≤b) = Φ(zb) − Φ(za)
  5. CI: x̄ ± z × σ

Soal Uji-t

  1. Tentukan H₀ dan H₁
  2. Pilih α (biasanya 0.05)
  3. Hitung t = (x̄₁−x̄₂) / √(s₁²/n₁ + s₂²/n₂)
  4. Hitung df (Welch)
  5. Cari ttabel dari tabel t
  6. |thitung| > ttabel? → Tolak / Gagal tolak H₀
  7. Tulis kesimpulan dalam konteks soal

Soal Interpolasi

  1. Identifikasi variabel: mana x, mana y
  2. Cari dua titik yang mengapit nilai target
  3. Terapkan rumus: y = y₁ + [(x−x₁)/(x₂−x₁)] × (y₂−y₁)
  4. Untuk inverse: tukar peran x dan y

= (x̄₁ − x̄₂) / √(s₁²/20 + s₂²/20)

df = (s₁²/n₁ + s₂²/n₂)² / [(s₁²/n₁)²/(n₁−1) + (s₂²/n₂)²/(n₂−1)]

Bulatkan df ke bawah (floor)
